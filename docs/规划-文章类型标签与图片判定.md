## 一、要解决的两个问题（假设）

### 问题 1：缺少"文章类型"维度 → 不该入卡的文章也进了卡片

**现状**：`app/classify.py` 只有**"反应类型"**一个维度（氧化 / 还原 / 偶联 / 保护脱保护 …），
是关键词规则；**没有"文章类型"维度**。

**需求**（用户 2026-09-17）：区分
`方法学` / `全合成` / `合成路线探索` / `合成工艺探索` / `综述` / `其它`，
并据此决定是否入卡。

**当前策略**：**只收集"方法学"入卡**；其余类型**只打标签、暂不入卡**，
但数据与标签保留，**将来可按需部分入卡**。

### 问题 2："这张图是不是反应式"的判断不可靠

**现状**：

| 环节 | 做法 | 失效点 |
| --- | --- | --- |
| `app/ingest.py` | 按图注（Scheme / Figure + 编号）裁图 | 仪器流程图、示意图也叫 "Figure" |
| `app/vision.py::classify_image` | 让视觉模型在 reaction / scope / mechanism / conditions / other 里选一个 | **"带箭头的流程图"看起来就像反应式**（都有箭头、方框、文字） |

**失效实例（KC-0009）**：一张 **HPLC/MS 仪器流程图**被判为 `reaction`，
占据了"文章的典型反应式"槽位。

**假设**：判断"是不是反应式"，最可靠的依据是**"图里有没有化学结构"**，
而不是文字多少或版面特征。

#### 支撑证据（2026-09-17 实测，用 chem-ocsr 的 OCSR）

| 图 | confidence | valid | 判定含义 |
| --- | --- | --- | --- |
| HPLC/MS 仪器流程图（KC-0009 误判图） | **0.0** | **false** | 干净否定 |
| 单结构裁片（化合物 52） | 0.588 | true | 是结构式 |
| 整张反应式图（KC-0006） | 0.74 | true（含 `*`、多片段） | 是结构式，但需先分割 |

> 那张流程图的原始输出：`confidence=0.0`、`valid=false`、
> `raw_smiles` 是一长串孤立碳（`C.C.C.C…`）与无意义稠环 → 从化学语义上被否掉。

## 二、判断方法

### 2.1 文章类型（**多标签 + 可核查证据**）

**主标签**（互斥）与 **副标签**（多选）两级：

| 主标签 | 含义 | 默认入卡 |
| --- | --- | --- |
| `methodology` | 方法学：讲一个 / 一类反应，通常有底物范围 | ✅ |
| `total_synthesis` | 全合成：目标是某个（天然）分子 | ❌（保留，可补卡） |
| `route_exploration` | 合成路线探索 / 条件筛选 | ❌（同上） |
| `process_chemistry` | 合成工艺 / 放大 / 绿色化学 | ❌（同上） |
| `review` | 综述 | ❌（特例：含人名反应条目时可单独入） |
| `other` | 分析 / 物性 / 理论 / 材料 | ❌ |

副标签：`has_scope`（有底物范围表）、`has_mechanism`、`has_scaleup`、`named_reaction`。

**判断三手段**：

1. **结构化证据（最可靠、可回归）**——从全文找这些句式 / 章节信号：
   - 全合成：`total synthesis`、`formal synthesis`、`retrosynthetic analysis`、`key steps`
   - 方法学：`we report a general method`、`substrate scope`、`broad substrate`、`catalytic`
   - 工艺：`scale-up`、`kg-scale`、`pilot`、`process development`
   - 综述：期刊 review 栏目、参考文献数量级
2. **LLM 判定（补覆盖）**：输入标题 + 摘要 + 章节标题，
   输出 **主标签 + 副标签 + 置信度 + 原文证据句**。
   ⚠️ **必须要求引用可核查的原文句**（能在正文里搜到），否则幻觉无法发现、也无法回归测试。
3. **特征辅助**：是否有 "Substrate Scope" 图表、正文反应式数量。

**流程**：规则 / 特征给候选 + 证据 → LLM 裁决（带证据）→ 低置信度进人工待审。

### 2.2 图片判定（**三段式 + 五档结论**）

```
① 便宜规则（0 成本）       尺寸 / 长宽比 / 是否照片（色彩分布）/ 图注关键词
        ↓ 候选图
② 视觉模型结构化提问        "图中是否存在键线式结构？你看到了哪些元素符号？"（要证据）
        ↓ 候选图
③ OCSR 化学证据（3–6 秒）   confidence > 阈值 且 RDKit 可解析 且 原子数 ≥ N  → 确认
                            confidence = 0 或 invalid                      → 否定
                            其它                                          → 不确定 → 人工
```

**成本估算**：一篇论文通常 10–30 张候选图，前两段先筛掉大部分，
第三段只跑 5–10 张 → **20–60 秒/篇**，离线批处理可接受。

**五档结论**（不设"是/否"二值，因为三类图都含化学结构、只是版式不同）：

| 结论 | 特征 |
| --- | --- |
| `scheme` | 1–2 个结构 + 箭头 |
| `scope` | 多个结构 + 网格 / 表格版式 |
| `mechanism` | 结构片段 + 弯箭头 |
| `not_chemical` | 流程图 / 照片 / 光谱 / 图表 / 示意图 |
| `uncertain` | 证据不足 → 人工 |

### 2.3 与 chem-ocsr 的接口（由该项目提供）

| 需要 | 说明 | 状态 |
| --- | --- | --- |
| **批量模式** | 一次进程处理多张图，模型只加载一次（否则每张图白付 3.6 s 加载） | ⬜ 待 chem-ocsr 实现（0.5 h） |

## 三、入卡策略（用户 2026-09-17 明确）

**四条设计要求**（"以后能按需入卡"的前提）：

1. **标签与卡片解耦**：入库时只打标签；卡片生成是独立步骤，可按标签筛选、可批量补跑。
2. **原始数据全部保留**：即使不入卡，正文、图片、图注、判定结果都要落库——
   否则将来想入卡就得重新抓一遍。
3. **提供"按标签批量补生成卡片"的入口**（一条命令 / 一个按钮）。
4. **标签可人工修改**，并记录来源（自动判错时能纠正，且不被下次重跑覆盖）。

### 成本取舍（重要）

| 步骤 | 成本 | 策略 |
| --- | --- | --- |
| 文章类型标注 | 便宜（一次 LLM 或纯规则） | **全量跑** |
| 图注提取 + 图片判定 | 中等（可缓存） | **全量跑**（将来入卡要用） |
| **全文结构化抽取（长文 LLM）** | **贵** | **只对入卡的文章跑**；非入卡文章标 `extract_status=pending`，将来补跑 |

这样现在几乎不增加成本，而"以后想入卡"的路径是畅通的。
